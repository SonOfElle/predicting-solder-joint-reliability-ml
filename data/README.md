# Data

## Overview

This directory holds the raw solder joint reliability dataset, the regeneration path for synthetic data, and the provenance and licensing notes for both.

The real dataset contains **450 samples**. Each sample is one solder joint under one thermal cycling condition. Each sample has **24 feature candidates** and one target: **measured lifetime in hours**.

The synthetic dataset contains **5,000 samples** generated by a GAN trained on the 450 real samples. It is not committed. It is regenerated via `make data`.

## Directory layout

    data/
    ├── raw/                  # 450 real samples, committed
    │   └── Data_Matrix_*.txt
    ├── synthetic/            # 5,000 GAN samples, gitignored
    │   └── Data_Matrix_*.txt
    └── README.md             # this file

## Provenance of the real data

The 450 real samples originate from the dataset published alongside:

> V. Samavatian, M. Fotuhi-Firuzabad, M. Samavatian, P. Dehghanian, and F. Blaabjerg, "Correlation-driven machine learning for accelerated reliability assessment of solder joints in electronics," *Scientific Reports*, vol. 10, no. 1, p. 14821, 2020. doi: 10.1038/s41598-020-71926-7.

That paper is the source of the CDNN baseline. It is also the source of the 450 real samples used in this thesis. The samples are finite element model (FEM) simulations, not physical measurements from a lab. The lifetime values are simulated useful lifetime, not observed failure times.

The original files are plain text matrices named `Data_Matrix_No.txt`, where `No` is an index. Each row is one solder joint. The columns are the 24 features followed by the measured lifetime.

This thesis did not collect new data. It reused the Samavatian et al. dataset. That reuse is the reason the baseline comparison exists at all: same data, same task, different model family.

## Feature dictionary

The 24 feature candidates, in the order they appear in the raw text files, are:

| # | Feature | Unit | Notes |
|---|---------|------|-------|
| 1 | Hot dwelling temperature | °C | Temperature held during the hot dwell phase |
| 2 | Solder density | g/cm³ | Bulk solder material |
| 3 | Upper layer density | g/cm³ | Adjacent layer above the joint |
| 4 | Lower layer density | g/cm³ | Adjacent layer below the joint |
| 5 | Hot dwelling time | min | Duration at hot dwell temperature |
| 6 | Solder CTE | 10⁻⁶/°C | Coefficient of thermal expansion, solder |
| 7 | Upper layer CTE | 10⁻⁶/°C | Coefficient of thermal expansion, upper layer |
| 8 | Lower layer CTE | 10⁻⁶/°C | Coefficient of thermal expansion, lower layer |
| 9 | Heating ramp | °C/hour | Rate of temperature increase |
| 10 | Solder melting temperature | °C | Solidus/liquidus transition, solder |
| 11 | Upper layer melting temperature | °C | Adjacent layer above |
| 12 | Lower layer melting temperature | °C | Adjacent layer below |
| 13 | Cold dwelling temperature | °C | Temperature held during the cold dwell phase |
| 14 | Solder Young's modulus | GPa | Stiffness, solder |
| 15 | Upper layer Young's modulus | GPa | Stiffness, upper layer |
| 16 | Lower layer Young's modulus | GPa | Stiffness, lower layer |
| 17 | Cold dwelling time | min | Duration at cold dwell temperature |
| 18 | Solder Poisson ratio | dimensionless | Transverse contraction ratio, solder |
| 19 | Upper layer Poisson ratio | dimensionless | Upper layer |
| 20 | Lower layer Poisson ratio | dimensionless | Lower layer |
| 21 | Cooling ramp | °C/hour | Rate of temperature decrease (negative) |
| 22 | Solder thickness | µm | Joint geometry |
| 23 | Solder width | mm | Joint geometry |
| 24 | Solder length | mm | Joint geometry |
| 25 | **Measured lifetime** | **hours** | **Target variable** |

The first 24 columns are feature candidates. Column 25 is the target.

Feature selection was not fixed in the original work. The thesis treats all 24 as candidates and lets the models and the GAN use them. Tree-based models and the CDNN did not require explicit selection. SVR and GPR used all 24 after scaling.

## Target variable

`Measured lifetime (hours)` is the simulated useful lifetime of the solder joint under the thermal cycling condition described by the 24 features.

The thesis notes that this is FEM-simulated lifetime, not physical test data. That matters for interpretation: the models are learning the behaviour of a simulation, not the behaviour of a physical joint. The negative R² on real data is partly a consequence of this and partly a consequence of the small sample size.

## Synthetic data

The synthetic dataset is generated by a GAN implemented in TensorFlow and Keras. It is trained on the 450 real samples. It produces 5,000 samples.

Key details:

- **GAN type:** fully connected generator and discriminator. The thesis does not use a convolutional GAN.
- **Input:** the 24 scaled feature candidates.
- **Output:** 5,000 synthetic rows with the same 25 columns as the raw data.
- **Seed:** fixed. See `src/solder_reliability/gan.py` for the seed value.
- **Two GANs:** the rebuild trains two GANs from the same architecture and seed, one on the fixed per-sample layout and one on the original C-order layout. Outputs are saved to `data/synthetic/synth_fixed.npy` and `synth_original.npy`. See `02_gan_synthesis.ipynb`.
- **Exact reproduction:** not guaranteed from source alone. TensorFlow version, GPU or CPU execution, and library versions affect the exact synthetic values. The handover decision is to publish the exact 5,000-sample synthetic dataset as a GitHub Release asset. That asset is the canonical synthetic dataset. Regenerating via `make data` produces a statistically similar but not bit-identical dataset.

This caveat is documented in the notebooks and in the repo README. It is not hidden.

## Regeneration

`make data` regenerates the synthetic dataset from `data/raw/`.

Expected behaviour:

- Reads the 450 real samples from `data/raw/`.
- Trains the GAN with the fixed seed.
- Writes 5,000 samples to `data/synthetic/`.
- Does not overwrite `data/raw/`.
- Does not commit anything to git. `data/synthetic/` is gitignored.

Exact reproduction of the published synthetic dataset requires the Release asset. `make data` is for regeneration, not for bit-exact replication.

## Preprocessing

The thesis applies the following preprocessing before modelling:

- **Scaling:** MinMaxScaler to [0, 1] for SVR, GPR, and the GAN. Tree-based models (Random Forest, XGBoost) used the raw feature values.
- **Missing values:** the raw files are complete. The thesis does not describe imputation. If missing values appear, they are treated as an error, not silently imputed.
- **Train/test split:** the thesis does not state a fixed split ratio for all experiments. Learning curves vary the training set size. The final reported numbers use a held-out test set.
- **Outliers:** no outlier removal is described. The negative R² on real data suggests outliers were not removed and were not the cause of the failure.

If the refactored pipeline changes any of these choices, the change must be documented in the notebook and in `results/metrics.csv`.

## Known caveats

1. **The real data is simulated, not physical.** The target is FEM output, not measured failure time. This limits external validity.
2. **The real dataset is small.** 450 samples for 24 features. This is the core reason the ML models fail on real data and the reason the GAN was used.
3. **The synthetic data is not bit-reproducible from source.** The Release asset is the canonical version.
4. **The GAN does not preserve all statistical properties perfectly.** Measured on the rebuild's GAN output: the real target spans 3,986 hours (24,332 to 28,318) and the synthetic target spans 9,226 hours (22,374 to 31,600). The GAN widens the target distribution by roughly 2.3x. Several feature columns also drift, for example heating ramp mean shifts from 183 to 145 and cold dwell temperature mean from -21 to -25. Scaled RMSE is therefore not comparable across real and synthetic tracks without correcting for the spread difference. Every metric table in this repo reports both scaled and hour units, and `results/metrics.csv` carries a `target_spread_hours` column so the conversion can be verified.
